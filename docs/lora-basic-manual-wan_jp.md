#  概要

LoRa-BASICでは、LoRaWAN用のコマンド、変数、関数を使用してLoRaWANのエンドデバイスとしての動作が可能です
本マニュアルは、LoRa-BASICのLoRaWANモードについて記載しています。  

P2Pモードに関しては、***「LoRa-BASIC for LRA1 リファレンスマニュアル P2P編」*** を参照してください。  
LoRa-BASICの基本的な使用方法については、***「LoRa-BASIC for LRA1 リファレンスマニュアル 基本編」*** を参照してください。

なお、本マニュアルでは、LRA1モジュールを「デバイス」と表記します。

>地域・無線認証に関する注意  
>本マニュアルに記載する無線機能は、日本国内での使用を想定しています。日本国外での使用および各国・地域の無線規制・認証への適合についてはサポートしていません。  

## LoRaWANの仕様

LoRa-BASICのLoRaWAN仕様は以下のとおりです。

| 項目           | 仕様                                     |
|:---------------|:-----------------------------------------|
| バージョン     | LoRaWAN Specification Version 1.0.3      |
| 対応リージョン | AS923-1 ISM Band (Japan) 920MHz帯        |
| 対応クラス     | Class-A / C　（Class-Bは未サポート）     |
| Join方式       | OTAA / ABP                               |
| Data Rate      | DR0～6　（DR7のFSKには対応しません）     |
| ADR対応        | 対応 （アクティベートしたNetworkに依存） |
| Confirm対応    | Confirm / Unconfirm どちらにも対応       |
| その他         | 技術適合認定の範囲で動作                 |

> LoRaWANサーバーおよびGatewayは、「AS923-1LBT」に設定することを推奨します。  
> (LBTとは、「Listen Before Transmit」の略で、送信前にキャリアセンスを実行することを表します。)

## 通信モード

LoRa-BASICの通信モードには、**P2Pモード**と**LoRaWANモード**の２つの通信モードがあります。  

LoRa-BASICの基本機能はP2Pモードによるデバイス相互間での通信ですが、LoRaWANモードに設定することによってLoRaWAN対応のGatewayを介したLoRaWANネットワークのエンドデバイスとして動作します。  
LoRaWANモードでは、BASICの基本機能はそのままで、LoRaWANに関するコマンドと変数等が追加されます。  

LoRaWANモードとP2Pモードは切り替えて使用します。  
LoRaWANモードとP2Pモードを混在して同時に使用することはできません。  

LoRaWANモード中でもP2Pモードに関連するコマンドのいくつかは実行することができますが、正しい動作にはなりません。  
通信モードを切り替えるときは、*Wan_Mode*を変更してから*SSave*コマンドで保存したのち再起動してください。  
*Wan_Mode*の変更後に再起動しないでLoRa関連のコマンドを実行すると、正しく動作しない場合があります。

(詳細は*Wan_Mode*を参照)

# LoRaWANコマンド

LoRaWANモードでは以下のコマンドが使用可能です。

| コマンド名 | 内容 | 引数 |
|----|----|----|
| *Wan_Join* | アクティベーション(Join)を実行 | なし |
| *Wan_UnJoin* | アクティベーション(Join)を解除 | なし |
| *Wan_Tx* | アップリンクデータを送信 | \[ encode \] |
| *Wan_Rx* | ダウンリンクデーターを受信 (Class-C) | \[ timeout , \] \[ encode \] |
| *Wan_RxStop* | ダウンリンクデーターの受信を停止 | なし |
| *Wan_LinkChk* | リンクチェックMACコマンドを設定 | なし |
| *Wan_ChList* | チャンネルリストを表示 | なし |
| *Wan_ChAdd* | 使用チャンネルをチャンネルリストに追加 | chid, freq, dr-min, dr-max |
| *Wan_ChRemove* | 使用チャンネルをチャンネルリストから削除 | chid |

各コマンドの詳細については、それぞれの解説を参照してください。  
コマンド名の大文字/小文字は同様に扱われます。混同して使用可能です。  
これらのコマンドをP2Pモードで実行するとエラーとなります。  
LoRaWANのコマンドは完了までに時間がかかることがありますが、「Ctrl-C」で中断することはできません。（*Wan_Rx*コマンドを除きます）  
LoRaWANコマンドの実行結果は*Stat*変数に反映されます。（詳細は*Stat*を参照）  
LoRaWAN関連のコマンドと変数は接頭語の“*Wan\_*”から始まりますが、”*Wan\_*”を”*\#*
”で代用することができます。  
（例 ： “Wan_Join”→“#Join”、　“Wan_Tx”→“#Tx”、”Wan_Cnf=1”→”#Cnf=1” ）

## Wan_Join

アクティベーション(Join)を実行  
書式 ： *Wan_Join*  
引数 ： なし  
LoRaWANネットワークにアクティベーションします。  
*Wan_JoinMode*変数により、アクティベーションの方式が異なります。

| *Wan_JoinMode* | アクティベーション方式                |
|:--------------:|---------------------------------------|
|       1        | OTAA （Over-The-Air Activation)       |
|       2        | ABP （Activation By Personalization） |

*Wan_Tx*コマンドでデータを送信するには、本コマンドによるアクティベーションが必要です。  
現在のアクティベーション状態は、*Wan_JoinStat*で確認することができます。  
アクティベーションされている状態で*Wan_Join*コマンドを実行したときは、“already_joined”
を表示して現在のアクティベーション状態を継続します。あらためてアクティベーションするには一旦アクティベーションを解除してください。  
アクティベーションを解除するには、*Wan_UnJoin*コマンドを使用します。  
各アクティベーションの方式の動作については以下に解説します。

### Join - OTAA

OTAA （Over-The-Air Activation)方式でネットワークにアクティベーション(Join-Request)します。  
アクティベーションに成功すると “join_accepted”
と表示します。OTAAアクティベーションではネットワークからDevAddr、NwkSkey、AppSkey
が設定されるので、それらをLoRaWANの各変数から参照することができます。（LoRaWAN変数を参照してください）  
OTAAでアクティベーションを実行するには、*Wan_DevEui*、*Wan_JoinEui*、*Wan_AppKey*が設定されていて、それぞれの値がアクティベーションするネットワーク(LoRaWANサーバ)に登録されている必要があります。  
アクティベーションに失敗すると、LoRaWAN仕様に従って制限時間が経過するまでは次のアクティベーション要求を実行できません。そのため、Join-Requestのフレーム送信完了後から制限時間中に*Wan_Join*
(OTAA)コマンドを実行すると ”\*dutycycle_restricted” エラー(*Stat* = 7）となります。　この送信制限時間については、*Wan_DutyTime*変数を参照してください。  
ネットワークがアクティベーションを拒否するときは応答などを何も送信しないので、結果的に“\*timeout” エラー(*Stat* = 8)となります。  
OTAAでのアクティベーション実行時、*Wan_JoinDelay1*および*Wan_JoinDelay2*変数の値をJOIN_ACCEPT_DELAY、
JOIN_ACCEPT_DELAY2に設定します。AS923のデフォルトではそれぞれ5000msecと6000msecとなっているので、*Wan_Join*コマンド実行からアクティベートされるまで約6秒、タイムアウトは約7秒です。（受信Windowは各1000msec）  
アクティベーションの状態はFLASHに保存されDeep/Reset/電源ONの再起動時に復旧します。

### Join - ABP

ABP （Activation By Personalization）方式でアクティベーションします。  
ネットワークとの送受信はありません。  
ABPアクティベーションを実行すると *“joined”* と表示します。  
ABPアクティベーションにはネットワークから事前に発行されたDevAddr、NwkSkey、AppSkeyを
*Wan_DevAddr*、*Wan_NwkSkey*、*Wan_AppSkey*
の各変数に設定しておく必要があります。  
*Wan_DevAddr*が０に設定されているときは、本コマンドのABPアクティベーション実行時に乱数で生成した値を設定します。ネットワーク側の設定によっては*Wan_DevAddr*
には事前に値の設定が必要です。  
ABPでのアクティベーション実行時、*Wan_RecvDelay1*および*Wan_RecvDelay2*変数の値をRECEIVE_DELAY1,
RECEIVE_DELAY2に設定します。この値はアクティベーション中も再設定可能です。  
アクティベーションの状態はFLASHに保存されDeep/Reset/電源ONの再起動時に復旧します。  
  
※制限事項 ：
ABPの動作はサーバーやネットワーク環境によっては正常動作しない場合があります。

```
 >Wan_JoinMode=1  
 OK  
 >Wan_Join  
 *timeout  
 OK  
 >Wan_Join  
 *dutycycle_restricted  
 OK  
 >Wan_Join  
 join_accepted  
 OK  
 >? Wan_JoinStat  
 1  
 OK  
 >Wan_Tx  
 OK
```

### Join状態の保存と復旧

Join状態の各種パラメーターは自動でFLASHに保存され、Deep/リセット/電源断からの再起動時に復旧します。  
デフォルトでは以下の３つの動作が自動で実行されるので、基本的にユーザーでの操作は必要ありませんが、  
動作環境やFLASHの寿命の兼ね合いから、Ctrl変数へのビット設定で保存方法を選択することができます。

Ctrl変数のビット位置については、「Ctrlのビット設定」の項目を参照してください。

#### RAMへの保存

Join状態はデフォルトでFLASHとRAMバッファに同時保存されますが、Ctrl変数を「RAMへの保存のみ」に設定するとFLASHへの保存を無効にしてRAMのみに保存します。　FLASHへの保存を無効にしてもJoin状態がRAMに保存されていると、リセットからの復帰時にはJoin状態が復旧します。Join状態がFLASHとRAMに同時保存されているときもリセット（ハードウェアリセット、Resetコマンド、ウォッチドッグリセット）による再起動時はRAMからの復旧が優先されます。（Deepからの復帰時によるリセット起動ではJoin状態はRAMにバックアップされないことに注意してください。）

#### FLASHへのJoin情報の保存

Join状態の各種情報は*Wan_Join*、*Wan_UnJoin*コマンドの実行が終了した時にFLASH/RAMに保存されます。  
一般的にアクティベーション操作は頻繁に実施されないので、Join情報の保存はFLASHの寿命にほとんど影響しませんが、デフォルトでは送受信時にUp/DownLinkCounterやChannelが更新されてFLASH/RAMに保存されるのでFLASHの寿命に影響します。Ctrl変数を「FLASHにはJoin情報のみ」に設定すると送受信時にこれらを保存せず、Join状態中にネットワーク側からのMACコマンドによって各種パラメーターの変更があった場合もそれらは自動で保存されません。（RAMには保存されます。またCtrl変数の設定でMACコマンド送受信時に自動保存することができます。）  
*Wan_Save*コマンドを使用すると、各種パラメーターをFLASHに保存することができます。

#### FLASHへのカウンタ値の保存

デフォルトでは送受信時にUp/DownLinkCounterやChannelが更新されてFLASH/RAMに保存されます。  
ゲートウエイが受信したフレームをLoRaWANサーバーに転送したとき、そのフレームのUp/DownLinkCounterがLoRaWANサーバーで管理しているカウンタ値未満だと既に受信済みとみなされ、LoRaWANサーバーでそのフレームは破棄されます。したがって、アクティベーション中は常に最新の「カウンタ値の保存」が必要です。  
ただし、「UpLinkCounterを固定する」とした場合はこの処理を回避することができます。（LoRaWANサーバー側も設定が必要です。）

#### FLASHへの書き込み回数

本デバイスのFLASHメモリは平均10万回の消去/書き込みが可能ですが、Up/DownLinkCounter等のカウンタ値をFLASHに保存する際は1つのセクタを分割して徐々に使用しているので、約150万回までの書き込みが可能な事を想定しています。これは、約4分毎のフレーム送信を10年間継続したときの回数よりも多いです。  
(60/4) x 24 x 365 x 10 = 1,314,000  
ただし、周辺温度や電圧などの動作環境やデバイスの個体差によってはこれ以下になることもあります。

## Wan_UnJoin

アクティベーション(Join)を解除  
書式 ： *Wan_UnJoin*  
引数 ： なし  
LoRaWANネットワークからアクティベーションを解除します。  
OTAAおよびABPでのアクティベーションを解除し、*“Unjoined”*
と表示します。  
ネットワークとの通信はありません。本デバイス内部のアクティベーション状態が解除されるだけとなります。  
OTAAでアクティベーションしていた場合、*Wan_DevAddr*、*Wan_AppSkey*、*Wan_NwkSkey*
が0にクリアされます。  
ABPでアクティベーションしていた場合、それぞれの設定値はクリアされません。  
Class-Cでダウンリンク受信待機中の時は受信待機状態が解除されます。

```
 >? Wan_JoinStat  
 1  
 OK  
 >Wan_Tx  
 OK  
 >Wan_UnJoin  
 Unjoined  
 OK  
 >Wan_Tx  
 *not_joined  
 OK  
 >? Wan_JoinStat  
 0  
 OK
```

## Wan_Tx

アップリンクデータを送信  
書式 ： *Wan_Tx* \[encode\]  
encode ：
受信したダウンリンクデーターの表示エンコーディングを指定します。

| encode | 受信データの表示形式                                 |
|:------:|------------------------------------------------------|
|   ％   | パーセントエンコーディングで表示                     |
|   ＆   | BASE64エンコーディングで表示                         |
|   ＄   | 16進数文字列で表示                                   |
|   ！   | STX/ETXで囲んだバイナリで表示                        |
|   ＊   | 表示しない                                           |
|   ～   | バイナリ値でそのまま表示　\<引数省略時のデフォルト\> |

送信バッファ(*Txd*)に格納された内容のアップリンクデータを送信します。送信データは*Wan_Tx*コマンドの引数に直接指定できません。  
アップリンクデータを送信するには、アクティベーションされている必要があります。（詳細は*Wan_Join*コマンドを参照）  
送信フレームのポート番号(FPort)には*Wan_FPort*の値が設定されます。(詳細は*Wan_FPort*を参照)

データ長は送信バッファの*Txd(7)*に設定しておいてください。*Txd*に文字列を設定するとデータ長は自動的に送信バッファの*Txd(7)*に文字列長が設定されます。(詳細は*Txd*を参照)  
データーレートは*Wan_Dr*の値です。DR毎に送信可能な最大データ長が異なります。この最大データ長を超えるデータを送信することはできません。その場合はDR値を調整してください。（詳細は*Wan_Dr*、*Wan_Length*を参照）  
*Wan_Adr*の値は送信フレームのADRとして送信しますが、ADR制御はネットワーク側の機能に依存します。(詳細は*Wan_Adr*を参照)  
*Wan_Cnf* = 0 (off)
のとき、送達確認はありません。したがって、再送制御はありません。  
*Wan_Cnf* = 1 (on)
のとき、送達確認を実施します。*Wan_Trial*の設定にしたがって再送制御をします。(詳細は*Wan_Trial*を参照)  
アップリンクデータの送信後、LoRaWAN仕様V1.0.3にしたがってネットワークからのダウンリンクデーターの受信を待ちます。このときにダウンリンクデーターを受信すると、次の書式で受信したダウンリンクデーターを表示します。

@\<RxRSSI\>,\<RxFPort\>,\<RxData\>  
受信したダウンリンクデーター\<RxData\>は引数のencodeに指定されたエンコーディングで表示します。  
また、以下に示す各変数に受信結果が反映されます。  
*Stat* = 10、*Rssi* = \<RxRSSI\>、*Rxd(6)* = \<RxFPort\>、*Rxd(7)* = \<RxData\>.Length、*Rxd(8～)* = \<RxData\>

この*Wan_Tx*コマンドに先立って*Wan_LinkChk*コマンドでリンクチェックが設定されていた場合、このアップリンクデータの送信フレームにリンクチェックMACコマンドが設定されます。ネットワークからリンクチェックの応答があるとその内容を表示します。（詳細は*Wan_LinkChk*コマンドを参照）  
Class-Cでダウンリンク受信中に*Wan_Tx*コマンドを実行すると、フレーム送信後にダウンリンク受信を再開します。  
（P2Pモードでは、*Recv*コマンドによる受信中に*Send*コマンドを実行すると、送信後に受信の再開はしません。）

```
 >Txd=$"01020304"  
 OK
 >Wan_FPort=50  
 OK  
 >Wan_Tx $  
 @-75,100,0a0b0c  
 OK  
 >? Stat  
 10  
 OK  
 >Wan_Tx $  
 OK  
 >? Stat  
 0  
 OK
```

## Wan_Rx

ダウンリンクデーターを受信  
書式 ： *Wan_Rx* \[timeout , \] \[encode\]  
timeout ： タイムアウト時間を
1/1000秒単位で指定します。\<省略時のデフォルトは -1 \>  
encode ： 受信データの表示エンコーディングを指定します。
(*Wan_Tx*コマンド参照)  
  
*Wan_Rx*コマンドは、Class-Cでダウンリンクデーターを受信します。  
本コマンドはClass-C (*Wan_Class* = 2)でのみ実行可能で、Class-C以外では
“\*incompatible_class”エラーとなります。また、アクティベーションされていない状態での実行は
”\*not_joined”エラーとなります。  
timeoutにはタイムアウト時間を1/1000sec単位で指定します。timeoutの値によって以下のように動作します。

| timeout | 内容 |
|:--:|----|
| \> 0 | 指定した時間が経過、または新たなダウンリンクデーターを受信すると終了します。 |
| = 0 | すぐにコマンドを終了します。 |
| = -1 | 新たなダウンリンクデーターを受信すると終了します。\<省略時のデフォルト\> |
| \< -1 | 新たなダウンリンクデーターを受信する度に表示します。（コマンドを終了しません。） |


受信中ではないときに*Wan_Rx*コマンドを実行すると受信を開始し、既に受信済みのダウンリンクデーターがあればそれを表示します。　　
「timeout=0」以外では、*Wan_Rx*コマンドの実行中にダウンリンクデーターを受信するとその内容を表示します。 
*Wan_Rx*コマンドを終了してもバックグラウンドでの受信を継続します。バックグラウンドでの受信は*Wan_RxStop*、*Wan_Join*、*Wan_UnJoin*コマンドによって停止します。バックグラウンドでの受信中にJoin状態が保存されて再起動したときは、アクティベーション中のままですが、アクティベーション直後と同様に受信が停止した状態で復旧します。  
*Wan_Rx*コマンドの実行中にCtrl-C、Breakがあるとコマンドを終了し受信を停止します。バックグラウンドでの受信も継続しません。（このとき、BASICのプログラムも中断します。）  
\[encode\]の指定および受信したダウンリンクデーターの表示は*Wan_Tx*コマンドと同様です。(*Wan_Tx*コマンドを参照)  
バックグラウンドでの受信中も*Wan_Tx*コマンドによるアップリンクデータの送信が可能です。（このとき、アップリンクデータ送信終了後にバックグラウンドでの受信に戻ります。）  
ダウンリンクの受信状況は*Stat*変数で確認することができます。ダウンリンクデーターの受信後、*Wan_Rx*コマンドで受信したダウンリンクデーターを表示するか「*Stat*
= 0」で*Stat*変数をクリアしないと、新たなダウンリンクデーターの受信があっても破棄されて受信バッファは更新されません。  
  
>注意事項：  
>LoRaWANサーバーでダウンリンクデーターをキューに入れたりプッシュしたりしても、サーバー側の状況によってはダウンリンクデーターが直ぐにはLoRaWANサーバーから送信されないことがあります。これらについてはLoRaWANサーバーの動作に依存しますので、サーバー側の仕様を確認してください。  
>また、バックグラウンド受信中にBASICプログラムが終了（エラーによる終了を含む）しても、バックグラウンド受信は継続されます。

```
 >Wan_Rx -1,$  
 @-75,50,010203  
 OK  
 >? Stat  
 10  
 OK  
 >Wan_Rx 0,$  
 OK  
 >? Stat  
 0  
 OK
```

## Wan_RxStop

ダウンリンクデーターの受信を停止  
書式 ： *Wan_RxStop*  
引数 ： なし  
*Wan_RxStop*コマンドは、Class-Cのバックグラウンドでのダウンリンクデーターの受信を停止します。  
本コマンドはClass-C (*Wan_Class* = 2)でのみ実行可能で、Class-C以外では“\*incompatible_class”エラーとなります。
また、アクティベーションされていない状態での実行は ”\*not_joined”エラーとなります。  
受信状態ではないときに本コマンドを実行しても動作に影響はありません。

## Wan_LinkChk

リンクチェックMACコマンドを設定  
書式 ： *Wan_LinkChk*  
引数 ： なし  
このコマンド後の*Wan_Tx*コマンドで送信するデータフレームに、LINK_CHECK_REQコマンドを設定します。  
LINK_CHECK_REQのあるフレームを受信したネットワークは、ダウンリンクに応答のLINK_CHECK_ANSを含んで送信するので、*Wan_Tx*コマンドでのフレーム送信時にその応答内容を表示します。  
この応答の内容によって、Gatewayにおける本デバイスからのアップリンクの受信状況がわかります。  
表示内容と書式は以下のようになります。  
*“#\<DemodMargin\>, \<NbGateways\>”*

| 項　目 | 内　容 |
|:--:|----|
| *\<DemodMargin\>* | 最後に正常に受信されたLINK_CHECK_REQコマンドのリンクマージン。(dB単位) |
| *\<NbGateways\>* | 最後のLINK_CHECK_REQコマンドを正常に受信したGatewayの数。(0〜255) |

ダウンリンクが受信できなかったとき、またはダウンリンクにLINK_CHECK_ANSが含まれていなかったときは表示しません。ダウンリンクでデータの受信があったときは、この表示に続いて受信データを表示します。  
本コマンドを実行すると、直前に受信したLINK_CHECK_ANSの情報はクリアされます。  
  
Join状態のときのみコマンド実行が可能です。（Unjoin状態で実行すると”\*not_joined”エラーになります。）  
*Wan_UnJoin*コマンドでJoin状態を解除するとLINK_CHECK_REQコマンドも解除されます。  
LINK_CHECK_REQコマンドがあるときは、送信可能な送信バイト数が1バイト分減ります。（*Wan_Length*変数参照）  
Join中にリセットしてもLINK_CHECK_REQは解除されません。  
  
*Wan_LinkChk* は、*Print*コマンド等で文字列として使用することができます。文字列の内容は*Wan_Tx*コマンド実行時の表示内容と同様です。
新たな*Wan_LinkChk*コマンドを実行するまで文字列の内容は同じです。  
*Wan_LinkChk*を数値変数として使用すると、現在のLINK_CHECK_REQコマンド要求状態がわかります。

```
 >Wan_LinkChk  
 OK  
 >? Wan_LinkChk  
   
 OK  
 >? 0+Wan_LinkChk  
 1  
 OK  
 >Wan_Tx $  
 #19,1  
 @-75,50,010203  
 OK  
 >? Wan_LinkChk  
 #19,1  
 OK
```

## Wan_ChAdd

使用チャンネルをチャンネルリストに追加  
書式 ： *Wan_ChAdd chid, Freq, dr-min, dr-max*

ABPのとき、使用チャンネルをリストに追加します。  
chidには3～15を、Freqには周波数(Hz)、dr-minにはDR範囲の最小値、dr-maxにはDR範囲の最大値を指定します。設定する値はLoRaWANサーバーの設定に合わせる必要があります。  
なお、chid=1,2はLoRaWANのデフォルトチャンネルのため変更できません。  
OTAAのときに本コマンドを実行してもエラーにはなりませんが、動作は保証されません。  
この設定値は保存されません。

## Wan_ChRemove

使用チャンネルをチャンネルリストから削除  
書式 ： *Wan_ChRemove chid*

ABPのとき、*Wan_ChAdd*コマンドで追加した使用チャンネルをリストから削除します。  
chidには*Wan_ChAdd*コマンドで追加したチャンネルのchidを3～15で指定します。  
なお、chid=1,2はLoRaWANのデフォルトチャンネルのため削除できません。  
OTAAのときに本コマンドを実行してもエラーにはなりませんが、動作は保証されません。  
この設定値は保存されません。

#### Defaultコマンドについて  
*Default*コマンドでLoRaWAN変数はデフォルト値に再設定されます。  
ただし、アクティベーション関連の変数およびデフォルト値のない変数は*Default*コマンドの影響を受けません。  
LoRaWANモードのときは、P2Pモードのみに関連する変数はデフォルト値に設定されません。  
同様に、P2PモードのときはLoRaWANモードのみに関連する変数はデフォルト値に設定されません。  
※Defaultコマンドの引数が-1の場合を除きます。

## Wan_Mode

LoRa-BASICの通信モードを設定します。  
範囲 ： 0, １ (デフォルト無し)  
通信モードを変更するときに設定します。

| *Wan_Mode* | 通信モード    |
|:----------:|---------------|
|     0      | P2Pモード     |
|     1      | LoRaWANモード |

*Wan_Mode*は*SSave*コマンドでFLASHに保存します。（*Wan_Save*コマンドでは保存されません）  
*Wan_Mode*で通信モードを変更したときは*SSave*コマンドで値を保存してシステムを再起動してください。  
通信モードの変更後に再起動せずに各LoRa関連(P2P/LoRaWAN)のコマンドを実行した場合の動作については保証されません。（正常動作しない可能性があります。）  
また、通信モードを切り替えても、BASICプログラムの内容や一般変数、配列変数の内容には影響しません。  
*Wan_Mode*は*Default*コマンドの影響を受けません。（Defaultコマンドの引数が-1の場合を除きます）  
本マニュアルでは、LoRaWANモード(*Wan_Mode* = 1)に設定されたときの動作について解説しています。  
P2Pモード(*Wan_Mode* = 0)での動作については ***「LoRa-BASIC for LRA1 リファレンスマニュアル P2P編」*** を参照してください。

```
 >? Wan_Mode  
 0  
 OK  
 >Wan_Mode=1  
 OK  
 >SSave  
 OK  
 >Reset
```

## Wan_Class

LoRaWANのクラスを設定/参照します。  
範囲 ： 0, 2 （デフォルト：0）

| *Wan_Class* | LoRaWANクラス                    |
|:-----------:|----------------------------------|
|      0      | Class-A \<デフォルト\>           |
|      1      | Class-B (未対応につき、設定不可) |
|      2      | Class-C                          |

Class-Cに設定したときは、*Wan_Rx*と*Wan_RxStop*コマンドの実行が可能です。  
アクティベーションされている状態での*Wan_Class*の設定はエラーとなります。（同じクラスへの設定もエラーです。）  
*Wan_Class* を設定するときは*Wan_UnJoin*
コマンドでアクティベーション状態を解除してください。  

>※ *Wan_Class* は設定値を変更するとFLASHに自動保存されます。

```
 >? Wan_Class  
 0  
 OK  
 >Wan_Class=2  
 OK
```

>注意：  
>Class-C でアクティベーション(*Wan_Join*)しても、そのままでは受信状態にはなりません。
>アクティベーション後に受信状態にするには*Wan_Rx*コマンドを使用してください。（詳細は*Wan_Rx*コマンドの解説を参照してください。）

## Wan_JoinMode

アクティベーション方式を設定/参照します。  
範囲 ： 1, 2 （デフォルト：1）  
LoRaWANネットワークへのアクティベーション方式を設定します。  
*Wan_JoinMode* に設定する値は下表のようになります。

| *Wan_JoinMode* | アクティベーション方式                          |
|:--------------:|-------------------------------------------------|
|       1        | OTAA （Over-The-Air Activation)　\<デフォルト\> |
|       2        | ABP （Activation By Personalization）           |

*Wan_JoinMode*によって、*Wan_Join*コマンドでのアクティベーション方式を指定します。  
*Wan_JoinMode*を設定するときは、アクティベーションが解除されていなければなりません。すでにアクティベーション済みのときは、”\*denied”エラーとなります。（このときBASICの処理は止まりません。）  
各アクティベーション方式については、*Wan_Join*コマンドを参照してください。  
※*Wan_JoinMode* は設定値を変更するとFLASHに自動保存されます。

```
 >Wan_JoinMode=1  
 OK  
 >Wan_Join  
 join_accepted  
 OK  
 >? Wan_JoinStat  
 1  
 OK  
 >Wan_Tx  
 OK
```

## Wan_TxPwr

送信出力を設定/参照します。  
範囲 ： 0～7　（デフォルト：0）  
*Wan_TxPwr*に設定する値は下表のようになります。

| *Wan_TxPwr* | LoRaWAN規定 (EIRP) | 出力(dBm) |
|:-----------:|:------------------:|:---------:|
|      0      |      MaxEIRP       |    13     |
|      1      |   MaxEIRP - 2dBm   |    11     |
|      2      |   MaxEIRP - 4dBm   |     9     |
|      3      |   MaxEIRP - 6dBm   |     7     |
|      4      |   MaxEIRP - 8dBm   |     5     |
|      5      |  MaxEIRP - 12dBm   |     3     |
|      6      |  MaxEIRP - 14dBm   |     1     |
|      7      |  MaxEIRP - 16dBm   |    -1     |

(EIRP ： Equivalent Isotropically Radiated Power = 等価等方放射電力)  
LoRaWANモードでは、P2Pモードの*Pwr*変数による送信出力の設定には影響されません。  
デバイスの電源電圧が標準電圧(3.3V)より低い場合は、実際の送信出力が低くなる場合があります。  
*Wan_TxPwr*
は*SSave*コマンドでFLASHに保存してください。（*Wan_Save*コマンドでは保存されません）

```
 >Wan_TxPwr=2  
 OK  
 >? Wan_TxPwr  
 2  
 >Wan_Tx  
 OK
```

## Wan_Dr

データーレート(Data Rate)を参照/設定します。  
範囲 ： 0～6　（デフォルト：2）  
データーレートの値は下記の表のようになります。

| *Wan_Dr* | 設定 (Sf/Bandwidth) | ビット速度(bps) | 最大Payload長 |
|:--------:|:-------------------:|:---------------:|:-------------:|
|    0     |    SF12 / 125kHz    |       250       |       0       |
|    1     |    SF11 / 125kHz    |       440       |       0       |
|    2     |    SF10 / 125kHz    |       980       |      11       |
|    3     |    SF9 / 125kHz     |      1760       |      53       |
|    4     |    SF8 / 125kHz     |      3125       |      125      |
|    5     |    SF7 / 125kHz     |      5470       |      242      |
|    6     |    SF7 / 250kHz     |      11000      |      242      |

網掛けのデーターレートはデフォルトでは使用制限されています。（*Wan_Dr*変数への設定は可能です。）  
LoRaWANモードでは、P2Pモードの*Sf*, *Bw*, *Cr* には影響されません。  
実際に送信可能なPayload長は、最大Payload長よりも短くなる場合があります。（詳細は*Wan_Length*を参照）

*Wan_Adr* =1のとき*Wan_Dr*
=0に設定するとADR制御が有効になり、データーレートは動的になります。  
（詳細は*Wan_Adr*を参照)  
*Wan_Dr*
は*SSave*コマンドでFLASHに保存してください。（*Wan_Save*コマンドでは保存されません）

```
 >Wan_Dr=3  
 OK  
 >? Wan_Dr  
 3  
 >Wan_Tx  
 OK
```

したがって、LoRa-BASICでは **デフォルトで使用可能なData RateはDR2～5** です。
*Wan_Dr*変数には0～6を設定できますが、*Wan_Dr*変数に0または1が設定されていると、*Wan_Dr*変数の内容にかかわらずDR2が適用されます。（ADR制御が有効な場合を除きます）  
*Wan_Dr*変数に6が設定されていると、*Wan_Tx*実行時にエラー(\*no_free_ch)
になります。  
DR0とDR1は、Dwellを「制限なし」に設定したMACコマンド(TxParamSetupReq)をLoRaWANネットワーク側から本デバイスに送信することで使用可能となりますが、これについてはLoRaWANネットワークの運用に依存し、LoRa-BASICから設定や指定はできません。  
同様に、DR6を使用可能とするには、LoRaWANネットワークからの指定が必要です。

ポート番号はアプリケーション固有の値で、ユーザーが任意で決めることができます。  
*Wan_FPort*

```
 >Wan_FPort=100  
 OK

 100  
 >Wan_Tx

```

## Wan_Cnf

送達確認を参照/設定します。  
範囲 ： 0, 1  
*Wan_Tx*コマンドでデータフレームを送信するときに、送達確認を行うかどうかを設定します。

| *Wan_Cnf* | 送達確認                                              |
|:---------:|-------------------------------------------------------|
|     0     | 送達確認をしません　（Unconfirm）　　\<デフォルト値\> |
|     1     | 送達確認をします　 (Confirm)                          |

*Wan_Cnf* = 1(Confirm)のとき、*Wan_Tx*コマンドによるデータ送信時に送達確認と再送制御を実施します。  
再送制御は*Wan_Trial*の設定値にしたがいます。(詳細は*Wan_Trial*を参照)  
*Wan_Cnf*
は*SSave*コマンドでFLASHに保存してください。（*Wan_Save*コマンドでは保存されません）

```
 >Wan_Cnf=1  
 OK  
 >? Wan_Cnf  
 1  
 >Wan_Tx  
 *timeout  
 OK
```

## Wan_Adr

ADR (Adaptive Data Rate) を参照/設定します。  
範囲 ： 0, 1  
*Wan_Tx*コマンドでアップリンクデータを送信するとき、フレームにこのADRを設定します。

| *Wan_Adr* | ADR制御                  |
|:---------:|--------------------------|
|     0     | ADR-off \<デフォルト値\> |
|     1     | ADR-on                   |

*Wan_Adr* =1 (ADR-on)
に設定すると、LoRaWANネットワーク側にADR=ONが通知され、以下の条件でADR制御が有効になります。  
*Wan_Adr* =1で*Wan_Dr* =0に設定したときのみデーターレートが動的に変更されます。  
*Wan_Adr* =1で*Wan_Dr* =0以外に設定したときは*Wan_Dr*
のデーターレートが優先されます。

*Wan_Adr* =0のときは、ADR制御されずに*Wan_Dr* のデーターレートとなります。  
ADR制御はネットワーク側の動作に依存するので、LoRaWANネットワーク側の設定によってはADR制御が有効にならないことがあります。

## Wan_Trial

送信試行回数を参照/設定します。  
範囲 ： 1～8 （デフォルト：1）  
*Wan_Trial*
には、*Wan_Tx*コマンドでデータフレームを送信したときに確認応答が受信できなかった場合の、再送信の試行回数を設定します。
再送信は*Wan_Cnf* = 1(confirm) に設定されているときのみ実施されます。  
*Wan_Trial* = 1のときは、初回送信のみで再送信しないことを意味します。（ただし、タイムアウトエラーは発生します。）  
次の表のようにLoRaWAN仕様に従ってデーターレートアダプテーションを実行します。

| 送信回    | Data Rate     |
|-----------|---------------|
| 1（初回） | DR            |
| 2         | DR            |
| 3         | max (DR-1, 0) |
| 4         | max (DR-1, 0) |
| 5         | max (DR-2, 0) |
| 6         | max (DR-2, 0) |
| 7         | max (DR-3, 0) |
| 8         | max (DR-3, 0) |

*Wan_Trial*が１または2に設定されているときに確認応答を受信しなかった場合、DRは低下しないことに注意してください。  
再送信時にデーターレートアダプテーションによってDRが低下したとき、送信フレームのデータ長がそのDRの最大送信長を超える場合、DRは低下せずに現在のDRでフレームが再送信されます。  
（例 ：
DR3でデータ長が11byte以下のとき、5回目の送信はDR1となるところですが、DR1の最大データ長は0なので、4回目と同じDR2のまま送信します。）  
*Wan_Trial*
は*SSave*コマンドでFLASHに保存してください。（*Wan_Save*コマンドでは保存されません）

```
 >Wan_Trial=3  
 OK  
 >? Wan_Trial  
 3  
 >Wan_Tx  
 OK
```

## Wan_Length

現在のデーターレートで送信可能な送信バイト数を参照します。  
範囲 ： 0～242 （デフォルト： *Wan_Dr*による）  
この変数は参照のみ可能です。値を設定することはできません。  
ペイロードに格納して送信可能なバイト数となります。  
この値を超えたデータ長を*Wan_Tx*コマンドで送信すると、\*invalid_data_lengthエラーとなります。  
各データーレートでの送信可能最大バイト数は、*Wan_Dr*変数の解説を参照してください。  
Dwellが制限あり（デフォルト）で*Wan_Dr*がDR0またはDR1に設定されている場合は、デフォルトのDR2に対応した送信可能バイト数の値となります。

```
 >Wan_Dr=2  
 OK  
 >? Wan_Length  
 11  
 OK
```

>※ 注意事項
> LoRaWANではデータの送信時にLoRaWANネットワークへコマンドや応答を送信することがあります。そのコマンドや応答にPayloadの一部が使用されるため、データーレート以外にADRやLoRaWANネットワークに対するコマンド・応答の送信待機状況によって送信可能バイト数も変化します。
>したがって、*Wan_Length*で参照されるデータ長が*Wan_Dr*変数で設定したデーターレートでの最大Payload長よりも少ない場合もあります。  
>*Wan_LinkChk*、*Wan_TimeReq*による要求があるとそれぞれ１バイト分が送信可能バイト数から減ります。

## Wan_DutyTime

送信制限時間を参照します。  
範囲 ： 0～  
この変数は参照のみ可能です。値を設定することはできません。  
現在の送信制限時間で単位はミリ秒となります。（制限中はカウントダウンされます。）  
  
LoRaWANではチャンネルを有効利用する観点から、送信後に既定の再送信制限時間があります。  
リージョンAS923ではフレームを再送信するときは以下のようになります。

| 送信時期 | 送信可能な総送信時間 | DutyCycleTime |
|----|----|----|
| 電源投入またはリセット後の最初の1時間内 | 総送信時間 \< 36秒 | 36s/1h = 1% |
| 次の10時間内 | 総送信時間 \< 36秒 | 36s/10h = 0.1% |
| 最初の11時間後からの24時間毎 | 総送信時間 \< 8.7秒 | 8.7s/24h = 0.01% |

*Wan_Join*コマンドのOTAAがタイムアウトした後に再度*Wan_Join*コマンドを実行してJoin-Requestを送信するときは、
以下のような「(送信時間 / DutyCycleTime) – 送信時間」 の送信制限時間となります。

| Join-Request送信時期                     | 制限時間                        |
|-----------------------------------------|---------------------------------|
| 電源投入またはリセット後の最初の1時間内 | 36.6sec (370ms/1% - 370ms)      |
| 次の10時間内                            | 369.6sec (370ms/0.1% - 370ms)   |
| 最初の11時間後からの24時間毎            | 3699.6sec (370ms/0.01% - 370ms) |

※Join-Requestのフレーム送信時間は約370msec  
Join-Requestの送信後は応答待ちが6000msecあるので、*Wan_Join*コマンド実行後はその分だけ制限時間が少なくなっています。
なお、Joinに成功した後の*Wan_Tx*では上記の制限時間はかかりません。ただし、Unjoin後の再Joinでは上記時間カウントは有効です。

*Wan_Tx*コマンドによるデータ送信では、LoRaWANサーバーからのMACコマンドによってDutyCycleTimeが指定されることがあり、フレーム送信後に指定された送信制限時間がかかります。この送信制限時間は*Wan_DutyTime*変数で参照することができます。（送信が頻繁なデバイスに対してサーバーから動的に指定することがあります。また、Unjoin後に再びJoinしても制限が解除されないこともあります。）

## Wan_LastTxCh

最後に送信に使用したチャンネルを参照します。  
範囲 ： 1～16  
この変数は参照のみ可能です。値を設定することはできません。

*Wan_Join*または*Wan_Tx*コマンドで送信に使用したチャンネル番号を参照します。  
このチャンネル番号は、*Wan_ChList*で表示される番号です。  
本デバイスの起動時がJOIN状態でなく、その後に送信されていないときは１となります。  
*Wan_Tx*コマンドでの送信時は、使用したチャンネル番号（*Wan_LastTxCh*変数と同じ値）が送信バッファのOffset
+４に設定されます。

## Wan_DwellStat

Dwellの状態を参照します。  
範囲 ： 0～3  
この変数は参照のみ可能です。値を設定することはできません。

現在のDwellの状態が次の値の論理和として参照されます。

| Dwell | 制限あり | 制限なし |
|-------|----------|----------|
| Up    | 1        | 0        |
| Down  | 2        | 0        |

Dwellは*Ctrl*変数で設定可能ですが、OTAAではLoRaWANサーバーから指定されます。  
デフォルトはUp/Downともに「制限あり」となります。  
  
Dwell制限あり ：
LoRaパケットの送信時間は400msec以下に制限されます。（デフォルト）  
Dwell制限なし ：
LoRaパケットの送信時間は4secまで制限が解除されます。  
   
一般的なLoRaWANネットワークでは、各デバイスのチャンネル占有時間を短くするために、Dwellを「制限あり」にしています。

## Wan_BatLevel

デバイスからLoRaWANネットワークへ報告するバッテリーレベルを設定・参照します。サーバーから取得する値ではありません。  
範囲 ： 0～255（デフォルト：0）

| 値 | 意味 |
|---:|------|
| 0 | 外部電源を使用 |
| 1 | バッテリー残量が最小 |
| 2～253 | バッテリー残量に応じた値 |
| 254 | 満充電 |
| 255 | バッテリーレベルを測定できない |

設定値は、LoRaWANネットワークから`DevStatusReq` MACコマンドを受信したとき、デバイスから`DevStatusAns`でネットワークへ報告されます。  
デバイスが電源電圧から自動算出する値ではありません。アプリケーションで測定した結果に応じて設定してください。  
この値は保存されません。システムを再起動すると0に戻ります。

## Txd, Txdw, Txdl

基本的な使用法はP2Pモードと同じです。（解説省略）  
*Txd*には*Wan_Tx*コマンドで送信するアップリンクデータフレームのペイロードに入れるデータを格納しておきます。  
*Txd*
に文字列を設定したときは、*Txd(7)*　のデータ長(Length)が自動的に設定されます。  
*Txd(0)～(6)*　には送信情報が送信完了時にシステムによって設定されます。　(詳細はバッファのフォーマットを参照)  
*Wan_Tx*コマンドでアップリンクデータを送信しても送信バッファの内容は変化しないので、再度*Wan_Tx*コマンドを実行すると同一データが送信されます。

```
 >Txd="12345"  
 OK

 >Wan_FPort=10  
 OK  
 >Wan_Tx  
 OK
```

## Rxd, Rxdw, Rxdl

基本的な使用法はP2Pモードと同じです。（解説省略）  
*Rxd*には*Wan_Tx*コマンドおよび*Wan_Rx*コマンド(Class-Cの場合)で受信したダウンリンクデーターのペイロード内容と受信情報(Rssi、Data Rate、FPort)が格納されます。  

- *Rxd(7)* ： 受信データ長(Length)  
- *Rxd(6)* ： ポート番号(FPort)  
- *Rxd(5)* ： Data Rate(DR)  
- *Rxd(4)* ： Rssiが設定されます。  
- *Rxd(0)～(3)* ： 未使用  

(詳細はバッファのフォーマットを参照)

```
 >Wan_Tx $  
 @-80,55,30313233  
 OK
 >? Rxd  
 01234  
 OK  
 >? Rxd(7)  
 4  
 OK  
 >? Rxd(6)  
 55  
 OK
```

P2Pモードと同様に、"#"をTxd, Rxdの代わりに使用することができます。  
設定時はTxdとして、参照時はRxdとして動作します。  
（「#L(0)=1」のように、Rxdl、Rxdw、Txdw、Txdlに使用することはできません。）  
  
例 ： 以下に示す左右の操作は同じ内容となります
```
 　#(0)=1    ↔  Txd(0)=1  
 　#="1234"  ↔  Txd＝"1234"  
 　A=#(7)    ↔  A=Rxd(7)  
 　Print #   ↔  Print Rxd
```

# P2Pモードと共通のLoRaコマンド

P2PモードとLoRaWANモードとにかかわらず、BASICの制御に関連する変数やコマンドはどちらのモードでも共通して使用します。これとは別に、LoRa通信に関わるコマンドと変数の中に、LoRaWANモードとP2Pモードのどちらにも共通に使用するものがあります。

LoRaWANモードでもP2Pモードで使用する変数(Sf, Bw,
…など)にアクセスすることが可能ですが、LoRaWANモードの動作に影響はありません。また、P2Pモード関連のコマンドで実行可能（Modeエラーにならない）なものもありますが結果は保証されません。LoRaWANモードでは、P2Pモードのみに適用されるコマンドや変数を使用しないことを推奨します。

## \#?（設定表示）

書式 ：　#?  
LoRaWANの各種設定値やその他設定情報を一括表示します。  
P2Pモードのときとは表示内容が異なります。（一部共通）  
また、*Wan_JoinMode*や設定レベルによっても表示内容が若干変わります。

```

 DevId=$"70b3d559e01d4dbe"
 Wan_Mode=1[Wan]
 Class=0\[A]
 JoinMode=1[OTAA]*
 TxPwr=0[13dBm]
 Dr=2

 Cnf=0

 Trial=1
 DevEui=$"0123456789abcdef"
 JoinEui=$"0123456789abcdef"  
 DevAddr=$12345678
 Ctrl=$00000000
 Echo=1[On]
 Auto=""  
 >
```

## SSave

書式 ： SSave

設定値をFLASHメモリーに保存します。  
ここで保存した設定はシステム起動時に自動的に読み込まれます。  
P2PモードおよびLoRaWAN
モードに関わらず、どちらの設定値もFLASHメモリーに保存します。  
FLASHメモリーに保存された設定値は、SLoadコマンドおよびシステム起動時に読み込まれます。  
LoRaWANのアクティベーションに関連する値は保存しません。（詳細はLoRaWAN変数を参照）

## SLoad

書式 ： SLoad  
設定値をFLASHメモリーから読み出します。  
P2PモードおよびLoRaWAN
モードに関わらず、どちらの設定値もFLASHメモリーから復元します。  
SSaveでFLASHメモリーに保存した設定内容を読み出すことができます。

LoRaWANのアクティベーションに関連する値は変更されません。

## Default

書式 ： Default \[引数\]

引数が指定されていないとき、および引数が-1以外のときは以下の動作となります。

LoRaWAN変数およびその他設定をデフォルト値に再設定します。  
LoRaWANモードのときは、P2Pモードのみに関連する変数(*Sf*, *Bw,*
…など)はデフォルト値になりません。  
LoRaWANモードとP2Pモードに共通の変数や設定値はデフォルト値になります。  
LoRaWANのアクティベーションに関連する変数は変更しません。（詳細はLoRaWAN変数を参照）  
*Default*コマンドのみではFLASHへの保存は行われません。

# P2Pモードと共通のLoRa変数

## Rssi

受信Rssiを参照します。  
範囲 ： -157～0 (デフォルト値なし)  
*Wan_Tx*コマンドでネットワークからダウンリンクを受信したときのRssi値が設定されます。  
*Rssi*が表す「Rssi (Received signal strength
indication)：受信信号強度情報」の単位はdBmです。  
ダウンリンクを受信するたびに最新のRssiに更新されます。  
ダウンリンクのデータ受信時は、受信バッファの*Rxd(4)*
にも同じ値が設定されます。  
受信データがなくても送達確認などのダウンリンクを受信するとその受信フレームのRssi値が設定されますが、受信バッファの*Rxd(4)*
は更新されません。  
*Wan_Join*コマンドによるJoin-Requestへの応答(Join-Acceptフレーム)受信などは対象にはなりません。  
*Rssi*は参照のみ可能です。値を設定することはできません。基本的にP2Pモードの*Rssi*と同様です。

```
 >Wan_Tx $  
 @-50,10,beef  
 OK  
 >? Rssi  
 -50  
 OK
```

## Snr

受信Snrを参照します。  
範囲 ： -128～127 (デフォルト値なし)  
*Wan_Tx*コマンドでネットワークからダウンリンクを受信したときのSnr値が設定されます。  
*Snr*が表す「Snr (Signal-to-Noise Ratio)：信号対雑音比」の単位はdBです。  
ダウンリンクを受信するたびに最新のSnrに更新されます。  
受信データがなくても送達確認などのダウンリンクを受信するとその受信フレームのSnr値が設定されます。  
*Wan_Join*コマンドによるJoin-Requestへの応答(Join-Acceptフレーム)受信などは対象にはなりません。

*Snr*は参照のみ可能です。値を設定することはできません。基本的にP2Pモードの*Snr*と同様です。

```
 >Wan_Tx $  
 @-50,10,beef  
 OK  
 >? Snr  
 8  
 OK
```

## Xtal32k

低速クロックを設定します  
範囲：　０，１  
０： 内部Crを使用します  
１： 外部接続の水晶振動子を使用します  
上記以外の値は無視されます。

低速クロック(32.768kHz)を外部クリスタルまたは内部Crに設定します。  
変数への設定直後に低速クロックが切り替わります。  
この変数は*SSave*コマンドで設定保存され、システム起動時にはこの変数による低速クロックが有効となります。  
外部に水晶振動子(32.768kHz)を接続したときのみ、”1”（外部）に設定してください。水晶振動子を接続せずに”1”を設定したときはエラーになります。ただし、ハードウェアの状態によってはハングアップする場合があります。  
Xtal32k変数はDefaultコマンドでは初期化されません。  

>※補足説明
>Ver1.10.a以前は外部水晶振動子を接続しないとLoRaWANの安定動作ができませんでしたが、  
>Ver1.10.b以降は外部水晶振動子を接続しなくてもLoRaWANの安定動作が可能となりました。  
>ただし、外部水晶振動子を接続したほうがアイドル動作中の消費電力が若干少なくなります。  

>DeepコマンドによってSleepするときは、低速クロックを内部Crに設定した方が待機中の消費電力を低くすることができます。
>デバイスの水晶振動子の接続方法等についてはハードウェアマニュアルを参照してください。

```
 >Xtal32k=0  
 OK  
 >? Xtal32k  
 0  
 OK  
 >Xtal32k=1  
 OK  
 >? Xtal32k  
 1  
 OK
```

# 設定レベル

LoRa-BASICにはパラメーターの設定変更を防止する目的で設定レベルがあります。  
*Pass*変数に特定の値を設定することで設定レベルを管理レベルに変更することができます。  
管理レベルで設定変更可能な変数については、各変数の解説を参照してください。  
設定レベルはユーザーが意図しない変数設定を防止することを目的としていますので、セキュリティ的な目的での使用は想定していません。  
プロテクトモードはBASICプログラムの参照を防止することを目的としています。

## Pass

設定レベルを設定する

詳細は、***「LoRa-BASIC for LRA1 リファレンスマニュアル 基本編」*** の *Pass*変数を参照してください。
