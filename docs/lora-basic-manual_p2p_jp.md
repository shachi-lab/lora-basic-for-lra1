#  概要

LoRa-BASICでは、LoRa制御用のコマンド、変数、関数を使用してLoRaパケットの送受信をすることができます。  
本マニュアルでは、LoRaを使用したプライベート通信のLoRa-P2Pモード（以下、P2Pモードと略）について記載しています。  

LoRaWANモードに関しては、***「LoRa-BASIC for LRA1 リファレンスマニュアル LoRaWAN編」*** を参照してください。  
LoRa-BASICの基本的な使用方法については、***「LoRa-BASIC for LRA1 リファレンスマニュアル 基本編」*** を参照してください。

なお、本マニュアルでは、LRA1モジュールを「デバイス」と表記します。


>地域・無線認証に関する注意  
>本マニュアルに記載する無線機能は、日本国内での使用を想定しています。日本国外での使用および各国・地域の無線規制・認証への適合についてはサポートしていません。

# P2Pモード

本デバイスの出荷時は、LoRa通信の方式は **P2Pモード** に設定されています。   
P2Pモードでは、本デバイス同士が直接に通信することができます。  
他社製LoRaデバイスおよびLoRaWANモードとの相互接続はできません。  

*Wan_Mode* 変数の設定でP2P/LoRaWANの通信モードを切り替えることができます。   
*Wan_Mode* 変数については、***「LoRa-BASIC for LRA1 リファレンスマニュアル LoRaWAN編」*** の *Wan_Mode* 変数の項目を参照してください。

いくつかの変数はSsaveコマンドでFlashメモリーに保存し、Sloadコマンドで復元することができます。

## Modem

変調方式を指定します。  
範囲：0:FSK / 1:LoRa  
FSK変調では、Sf, Cr, Bwの指定は無効です。

## Pwr

送信出力を設定します。  
範囲：-4～13  
設定した出力で送信します。単位は（dBm）です。  
電源電圧が標準電圧(3.3V)より低い場合は、実際の送信出力が低くなる場合があります。

## Sf

拡散率(Spread Factor)を設定します。  
範囲：7～12  
LoRa方式でのSF7～SF12に該当します。  
Bw=9(500kHz)のときはSF10以上のみ設定可能です。

## Bw

帯域幅(Bandwidth)を設定します。  
範囲：６～９  
6 : 62.5kHz , 7 : 125kHz , 8 : 250kHz , 9 : 500kHz  
FSK方式ではBwの設定にかかわらず500kHzとなります。  
Bw=9(500kHz)はSF10以上のときのみ設定可能です。

## Cr

符号化率(Cording Rate)を設定します。  
範囲：1～4  
1 : 4/5 , 2=4/6 , 3: 4/7 , 4: 4/8  
LoRa方式の送信時のみ有効です。（FSK方式ではCrは使用しません。）  
LoRa方式の受信では受信パケットのヘッダーに含まれるCr情報でデコードされるため、受信時はこのCr変数の設定は使用されません。

## Ch

送受信チャンネルを設定します。

範囲 ： 24～61  
ここで設定されたチャンネルで送受信を行います。  
Ch変数を設定するとFrq変数の値にも反映されます。**  **
Bw=125kHz以下では、24～38はLowBand、39～61はHighBandとなります。  
Bw=250kHz以上では、24～37はLowBand、38～60はHighBandとなります。（Ch=61は設定不可）

## Frq

送受信周波数を参照します。  
範囲：920600～928000  
Ch変数で設定したチャンネルに対応する周波数を参照します。単位は(kHz)です。  
この変数は参照のみ可能です。設定はできません。

## Gid

グループIDを設定します。  
範囲：0～65535  
同じグループID(Gid)に設定されたデバイス間での送受信が可能です。  
別のグループIDから送信されたフレームは受信しません。  
SendコマンドおよびTxd変数に文字列を設定したときは、この変数の値が送信バッファのGidに自動設定されます。

## Own

自局IDを設定します。  
範囲：0～65535  
受信側で設定した自局ID(Own)と、送信側が送信したフレームの宛先ID(Dst)が一致したフレームを受信することができます。ただし、宛先IDが65535で送信されたフレームは自局IDにかかわらず受信します。  
送信フレームにはここで設定した自局ID(Own)も含むので、受信側では送信元を確認することができます。  
SendコマンドおよびTxd変数に文字列を設定したときは、この変数の値が送信バッファのOwnに自動設定されます。

## Dst

宛先IDを設定します。  
範囲：0～65535  
フレーム送信時の宛先ID(Dst)を設定し、受信側で設定した自局ID(Own)と一致した場合に受信されます。  
宛先IDが65535はブロードキャストとなり、送信されたフレームは受信側の自局IDにかかわらず受信されます。  
SendコマンドおよびTxd変数に文字列を設定したときは、この変数の値が送信バッファのDstに自動設定されます。

## Rssi

受信パケットのRssi値の参照  
範囲：-137～0  
最後に受信した受信フレームのRssiを参照します。単位は(dBm)です。  
この変数は参照のみ可能です。設定はできません。

## Stat

送受信状態およびLoRaエラーの参照  
範囲 ： 0～  
LoRaコマンドの実行で発生したエラーのエラーコードおよび送受信の結果を参照します。  
参照のみが可能ですが、０を設定するとStat変数はクリアされます。０以外は設定できません。  
エラー内容およびエラーメッセージとStat変数の関係は下表のようになります。

| Stat変数 | エラーメッセージ | 内　容 |
|:--:|----|----|
| 0 |  | エラーなし |
| 4 | no_free_ch | キャリアセンスエラー　（Ch使用中） |
| 5 | invalid_data_length | 送信データ長エラー |
| 8 | timeout | 受信タイムアウト |
| 9 | CRC_Error | 受信CRCエラー 　　　(Ctrl変数で有効に設定された場合のみ) |
| 10 |  | データーパケット受信 |
| 12 | error | その他のエラー 　　（動作継続可能なH/Wや内部エラーなど） |
| 上記以外 |  | P2Pモードには適用されません |

エラーメッセージが空欄の項目は、エラーではないのでエラーメッセージの表示はありません。

Recvコマンドでタイムアウト指定時などは、コマンドから戻った理由がパケット受信なのかタイムアウト（または他のエラー）なのかをStat変数で確認する必要があります。また、Recvコマンドによるバックグラウンド受信中は、このStat変数でパケット受信があったことをBASICプログラムの実行中に知ることができます。Stat変数が０以外の時はバックグラウンド受信で新たなパケットは受信しません。（Statが０以外でも転送機能は有効です。）

> ※ Stat変数はLoRaWANモードでも使用します。  
> P2PモードとLoRaWANモードとで共通の値のものと、各モード特有のものがあります。

## TxLen

送信可能バイト数の参照  
範囲：０～242  
送信可能なペイロードの最大バイト数を返します。  
この値は、LoRa設定（Sf, Bw, Cr, Ch）
の各パラメーターによって異なります。  
詳細については、「LRA1 ハードウェアマニュアル」を参照してください。

## AesKey

暗号化用の共通鍵を設定、参照します。  
範囲 ： 16バイト分の文字列*  *
AesKeyが設定されると、送受信時にパケットのデータ部を暗号化および復号化します。  
暗号化方式はAES128bitの共通鍵暗号方式です。  
AesKeyには128bit（16バイト）分の文字列を設定します。（16進数での設定を推奨します。）  
暗号化されるのはパケットのデータ部のみで、ヘッダー部（Own、Dst、Gid等）は暗号化されません。ただし、ヘッダー部も暗号化に使用されるので、AesKeyとデータが同じであってもヘッダー内容によって暗号化後のデータは異なります。  
送受信の際は、送信側および受信側の双方に同じAesKeyが設定されている必要があります。送受信で異なるAesKeyが設定されていると、データ内容を正しく復号できません。  
AesKeyに空文字列またはオールゼロが設定されると暗号化は無効になります。（デフォルトはオールゼロです。）  
AesKeyが無効のときは、Printコマンドおよび文字列は空文字列となります。  
“#?” コマンドでは、AesKeyの最後の4バイトは "xxxxxxxx"
と表示されるので、AesKeyを確認するにはPrintコマンドで表示してください。また、LoRaWANモードのときは "\#?"コマンドでAesKeyを表示しません。  
AesKeyは、SsaveおよびSload コマンドで保存と復元ができます。  
また、AesKeyは"Pload &" および "Psave &" でも使用されます。

例：
```
>AesKey=$"0123456789abcdef00000000deadbeef"
OK
>? AesKey
0123456789abcdef00000000deadbeef
OK
>AesKey=""
OK
>? AesKey
00000000000000000000000000000000
OK
```

## Sens

チャンネルのRssiを取得  
範囲： －１７８ ～ ０  
この変数を参照するとチャンネルを短時間だけ受信してそのRssi値を取得します。  
受信チャンネルはCh変数で指定します。  
Sens変数は参照のみで設定はできません。  
本変数の参照によってRssi変数への影響はありません。 

※P2Pモードでのみ使用可能です。WANモードではエラーになります。

```
 >? Sens
 
 -110  
 OK
```

WANモードでは本バッファの内容は上記とは異なります。  
送信バッファと受信バッファはお互いに独立しています。  
送信バッファはTxd/Txdw/Txdl/Txdm変数を使用して参照と設定ができます。  
受信バッファはRxd/Rxdw/Rxdl/Rxdm変数を使用して参照ができますが、設定はできません。  
2バイトサイズの内容 (Gid, Own, Dst) は「Little endian」です。Txdw, Rxdw
を使用した操作ができます。  
受信バッファは最後に受信したパケットで上書きされますが、送信バッファは送信が完了してもクリアされません。  
ブロードキャストの時はDstが65535 (\$FFFF)となります。

## Txd, Txdw, Txdl, Txdm

送信バッファの設定と参照

書式：Txd(式) または Txd

括弧を付けたときは、\[式\]で指定された送信バッファのオフセット位置からByte単位(8ビット)で参照または設定します。  
設定する値が255を超えるときは、下位8bitが有効です。  
丸括弧”(添字)” の代わりに角括弧”\[添字\]”を使用可能です。

例：
```
 Txd(7)=10 ： 送信長(Length)に10を設定します。  
 A=Txd(10) ： 送信Dataの10byte目を参照します。
```

括弧を付けずに式の指定が無い場合は、送信バッファの内容を文字列として参照または設定します。  
文字列を設定すると、バッファの送信データに文字列が格納されるとともにGid,
Own, Dst, Lenも自動的に設定されます。  
Print、Lprintコマンド中に記述した場合は、送信バッファのDataが文字列として表示されます。

```
>Txd=”1234”
OK
>Send
OK  
>Print Txd  
1234  
OK  
>A=1:B=2  
OK  
>Txd=””:Txd(7)=2:Txd(8)=A:Txd(9)=B:Send  
OK
```

注意：  
文字列による設定をしない場合はGid/Own/Dst/Lenは自動的に設定されませんので、Sendコマンドに先立って送信バッファ中にあるヘッダーの該当箇所にそれぞれの値を設定する必要があります。

「Txd=Null」を実行することでLen=0でその他設定を簡略化できます。

書式：Txdw(式)、Txdl(式) 、Txdm(式)

式で指定された送信バッファのオフセット位置から、TxdwはWord(16bit)、TxdlはLong
Word(32bit)で、TxdmはMiddle
Word(24bit)で参照または設定をします。エンディアンは、Little
endianです。アライメントはありません。  
丸括弧”(添字)” の代わりに角括弧”\[添字\]”を使用可能です。

例：
```
 Txdw(4)=\$1234      ： 宛先ID(Dst)に$1234を設定します。  
 Txdl(8)=\$12345678  ： Dataの先頭からの4バイト分に\$12345678を設定します。
```

送信バッファはSendコマンドによって送信します。

Sendコマンドの引数に文字列を指定した場合は、Txdに文字列を指定したのと同様に送信バッファに文字列が設定されてから送信処理が実行されます。

## Rxd, Rxdw, Rxdl, Rxdm

受信バッファの参照

書式：Rxd(式) または Rxd  

括弧を付けたときは、\[式\]で指定された送信バッファのオフセット位置からByte単位(8ビット)で参照します。  
丸括弧”(添字)” の代わりに角括弧”\[添字\]”を使用可能です。

Txd変数とは異なり、値の設定はできません。（参照のみとなります。）

例：  
```
 A=Rxd(9) ： 受信Dataの2byte目を参照します。
```

括弧を付けずに式の指定が無い場合は、受信バッファの内容を文字列として参照します。  
Print、Lprintコマンド中に記述できます。  
文字列長は受信バッファ中のLenに従います。

```
>Recv 0
OK
>Print Stat
10
OK  
>Print Rxd  
1234  
OK  
>Print Rxd(7),Rxd(8)  
4 49  
OK
```

書式：Rxdw(式)、Rxdl(式)、Rxdm(式)

式で指定された送信バッファのオフセット位置からRxdwはWord(16bit)、RxdlはLong
Word(32bit)で、RxdmはMiddle Word(24bit)で参照します。
エンディアンは、Little endianです。アライメントはありません。  
丸括弧”(添字)” の代わりに角括弧”\[添字\]”を使用可能です。  
  
例：  
```
　A=Rxdw(2)　： Aに送信元ID(Own)を取得します。
　A=Rxdｌ(8) ： AにDataの先頭から4バイト分（32bit）を取得します。
```

## \#を使用した送受信バッファの設定と参照

"#" をTxdとRxdのエイリアス（代わり）として使用することができます。  
設定時はTxdとして、参照時はRxdとして動作します。  
` "#L(0)=1" `
のように、Rxdl、Rxdw、Rxdm、Txdw、Txdl、Txdmに使用することはできません。  
  
例 ： 以下に示す左右の操作は同じ内容となります
```
　#(0)=1   ←→ Txd(0)=1  
　#=”1234” ←→ Txd=”1234”  
　A=#(7)   ←→ A=Rxd(7)  
　Print #  ←→ Print Rxd
```

# LoRa-P2P コマンド

## \#?

書式：#?

各種設定値を一括で表示します。

実行例
```
>#?
Sn=100386
```

## TxWave

書式：TxWave \[式\]  
プリアンブルのみを送信します。  
引数の式には、プリアンブルの送信時間を5～3999
(msec)で指定します。（省略できません。）  
送信時間に4000(msec)以上、およびChがHighBandのときは400(msec)以上を指定すると
”\*invalid_length” エラーになります。  
送信パラメーターにはCh、Sf、Bw、Pwr変数の設定値が使用され、Sf、Bwに応じて指定された時間で送信されるプリアンブルのシンボル数が変わります。  
指定した送信時間がプリアンブルの送信シンボル数の１２ビット未満となる場合は、指定時間にかかわらず１２シンボル分のプリアンブルが送信されます。（デバイスがSendコマンド等で通常に送信するデーターパケットは、自動的に１４シンボル分のプリアンブルが先行して送信されます。）  
Sendコマンドと同様に、本コマンドによるプリアンブル送信では送信前にキャリアセンスを実行します。  
Modem変数がLoRaモードのときのみ有効です。（FSKモードのときは何もせずにコマンドを終了します。）  
なお、受信側がCadコマンドでプリアンブルの検出をすることができます。

#### プリアンブルとは

デジタル通信において、受信側に対して「これからデータが送られてくる」ことを通知するためにデータ本体に先行して送信される決まったパターンのビット列のこと。（LoRaでは１情報ビットをLoRa変調したものを１シンボルといいます。）

## Cad

書式：Cad \[式１\] \[，式２\]  

プリアンブルの検出を待ちます。　（Cad = Channel Activity Detection）  
式１ ：
インターバル時間をmsec単位で指定します。０以下または省略時は連続受信となります。  
インターバル時間が指定されたときは間欠受信となります。この受信時間とプリアンブルの検出処理にかかる時間はSf、Bwの設定値によって異なり、おおよそ
(2^Sf +32）/ Bw (sec) です。（Sf=10,Bw=125kHzの場合、8.45msec）  
プリアンブル検出に必要な時間よりも指定したタイムアウト時間が短い場合、実際のタイムアウト時間は長くなります。  
式２ ：
タイムアウト時間をmsec単位で指定します。０または省略時はタイムアウト無しになります。  
タイムアウト時間で指定した時間が経過すると ”\*timeout”
を表示してコマンドを終了します。タイムアウト時間に負数を指定するとその絶対値がタイムアウト時間となり
”\*timeout”
を表示しません。コマンドがタイムアウトで終了したときは”Stat=8”
が設定されます。  
  
受信パラメーターにはCh、Sf、Bw変数の設定値が使用されます。（送信側も同じ設定である必要があります。）  
プリアンブルを検出すると、”Stat=0” でコマンドを終了します。  
タイムアウト時間で指定した時間が経過するか、「Breakキャラクタ/信号」が入力されるまで検出動作を継続します。

Modem変数がLoRaモードのときのみ有効です。（FSKモードのときは何もせずにコマンドを終了します。）  
Recvコマンドによるバックグラウンド受信中にCadコマンドを実行すると、バックグラウンド受信は終了します。  
  
Ch、Sf、Bwが同じであれば、デバイスが送信したLoRaパケットやプリアンブルだけでなく他社製LoRa無線機から送信されたLoRaパケットのプリアンブルも検出対象となります。（LoRa方式以外のプリアンブルは検出しません。）  
  
Cadコマンドの間欠動作でプリアンブル検出を行うと、Recvコマンドで連続受信するよりも低消費電力で受信動作を実行できます。そのため、CadコマンドとTxWaveコマンドを組み合わせることで、受信側がCadコマンドで待機しているところに、送信側がTxWaveコマンドでプリアンプルを送信して、これからパケットを送信することを通知することができます。このとき、プリアンブル送信時間をCadのインターバル時間よりも長くすることでプリアンブルが検出されやすくなります。ただし、Cadコマンドではデーターパケットの受信はできないことに注意してください。

# P2P転送機能

LoRaのP2P通信にはパケットの転送機能があります。  
転送機能を有効化するには、Ctrl変数の該当するビット(Ctrl=\$40000)を設定してください。

デフォルトは転送機能が無効に設定されています。

この転送機能では以下に説明するHop変数とFwdConf変数を使用します。

## Hop変数

Hop変数はパケットの最大転送回数（Hop値）を設定します。（デフォルトは０です。）  
パケットには転送送信される度に加算される「転送カウンタ」があり、「Hop値＞受信パケットの転送カウンタ」のときにパケットが転送送信されます。そのため、転送機能が有効(Ctrl=\$40000)でもHop=0のときは実質的に転送機能が無効になります。  
Hop変数の設定可能最大値は「７」となっているので、最大７台までのレピーターを経由できます。  
Ctrl変数で転送機能が有効になっていなくてもHop変数の設定と参照は可能です。  
転送機能が有効のときはHop変数が ”#?”
コマンドで設定一覧に表示されます。  
Hop変数はSsave/Sloadコマンドで保存と復元、Defaultコマンドで初期化ができます。

## FwdConf変数

デフォルトでは転送機能による送信は受信と同じ通信パラメーター(Sf,Bw,Cr,Ch)となりますが、FwdConf変数を設定することで受信とは異なる通信パラメーターによる転送送信が可能です。  
FwdConf変数は32ビットを８ビット毎に区切って各設定値を指定します。

| ビット | パラメーター | 設定範囲 |
|--------|--------------|----------|
| 0～7   | Sf           | 6～12    |
| 8～15  | Bw           | 6～9     |
| 16～23 | Cr           | 1～4     |
| 24～31 | Ch           | 24～61   |

例 ： ”FwdConf=\$1B01070C” \<-- Ch=27, Cr=1, Bw=7, Sf=12

設定範囲外の値を設定してもエラーにはなりませんが、転送による送信には反映されません。  
FwdConf変数は、以下の特別な値の設定が可能です。

FwdConf = -1 :
常に受信と同じ通信パラメーターで送信します。（デフォルト）

FwdConf = 0 :
現在の通信パラメーターを設定します。（参照時は0ではなく設定時の値となります。）

FwdConf変数はSsave/Sloadコマンドで保存と復元、Defaultコマンドで初期化ができます。

ビット毎に設定するのは間違えやすく面倒なので、通常通りに通信パラメーター（Sf/Bw/Cr/Bw）を設定した後に
”FwdConf=0”
で現通信パラメーターをFwdConfに設定してから現通信パラメーターを元に戻すほうが楽です。  
（※”FwdConf=0”
の直後のSloadは、現通信パラメーターと共にFwdConfも戻るので注意してください。  
　現通信パラメーター設定後、”A=FwdConf:Sload:FwdConf=A:Ssave”
と、操作することで対応できます。）

## 転送動作

### 転送動作の開始

Ctrl変数の転送機能が有効でHop変数が０以外に設定されているときに、P2PのRecvコマンドが実行されて受信状態になると転送機能が動作します。（転送機能が動作するのはRecvコマンドによる受信中のみです。）  
受信中に転送機能が動作しても表示はありませんが、転送による送信があると送信LEDが点滅します。

### バックグラウンドでの受信と転送

Recvコマンドの引数でタイムアウト時間に0が指定されるとバックグラウンドでの受信状態になりますが、転送機能もバックグラウンドで動作するので、BASICプログラムの動作中だけでなく、REPLモードでのコマンド入力待ち状態でも転送機能が働きます。このとき、バックグラウンドでの転送によるパケット送信が実行されると送信中はBASICプログラムやREPLモードでの入力動作が一時的に停止したようになります。

### パケットの送受信先

転送機能が有効になると、同一Gid宛の受信パケットは自己ID(Own)宛以外の全パケットを転送します。特定の宛先へのパケットのみの転送やブロックをすることはできません。ブロードキャスト(Dst=65535)のパケットまたは自己IDが全受信(Own=65535)のときは、自己ID宛として受信すると共にそのパケットは転送されます。  
宛先のデバイスが転送されたパケットを受信しても、そのパケットは本来の受信パケットとの違いはありませんが、受信バッファのＣｔｒｌにあるHopを参照することで転送されたパケットであることを知ることができます。

### 再転送と相互干渉

送受信したパケットは一定時間（約30秒間）履歴に保存して次の受信パケットと比較し同一パケットは再転送しないようにして転送ループを抑制しています。また、Sendコマンドで送信する度にパケットのシーケンス番号をカウントしているので、ペイロードの内容が同じでも新たなSendコマンドによる送信パケットは別パケットとして区別されます。

パケットを受信してから転送送信するまでのタイミングを乱数によって散らしています。これによって、互いの受信範囲が重なるレピーター同士でも干渉し難くしていますが、後発の方はキャリアセンスによって送信をキャンセルする可能性あります。

### 互換性

転送機能が無いバージョンのソフトや転送機能が有効になっていないデバイスは、転送によって送信されたパケットの受信ができないので本来の送信元から送信されたパケットしか受信できませんが、それらから送信されたパケットは転送機能が有効なデバイスによる転送の対象になります。

基本的に、P2Pモードでは所謂レピーターや子機、親機などの明確な違いはありません。  
転送機能が有効でHopが０以外になっていれば、受信状態の時は転送機能が働きます。

### ※チャンネル設定（要注意）

使用するチャンネルはLowBand「CH24～CH37(Bw=500kHzのときはCH36)」の使用を推奨します。  
HighBand「CH38～」では、技適の規定で連続送信ができません。  
（技適ではHighBandは送信時間の１０倍の休止時間が必要で、LoRa-BASICはこの規定動作を実装しています。）

```
>Ctrl=\$40000  
>Own=65535  
>Hop=1  
>FwdConf=-1
>Auto="Recv\$"  
>Ssave  
>Reset    <---- 再起動すると全受信パケットを16進数で表示しながら転送します。
```

# 文字列のエンコーディング、デコーディング


## LoRaコマンドのエンコーディング

LoRaコマンドでの送受信データの設定/表示に、各エンコード、デコードを適用することができます。

### Recvコマンドのエンコード

書式：Recv \[式\]

Recvコマンド
の引数の\[式\]に「＄」、「％」または「＆」にすると、受信データをエンコードして表示します。  
詳細はRecvコマンドを参照してください。

```
>Recv %  <----- Percent encode  
@-50,10, a123  
>Recv &  <----- Base64 encode  
@-50,10, YTAxMg==  
>Recv $  <----- Hexdecimal encode  
@-50,10,61303132
```

### Commコマンドのエンコード

書式：Comm \[式\]

Commコマンドの引数の式を「＄」、「％」または「＆」にすると、入力された文字列をデコードして送信します。  
また、この場合の受信データはエンコードされて表示します。  
  
Comm & \<----- Base64 encode/decode

Comm % \<----- Percent encode/decode  
Comm \$ \<----- Hexdecimal encode/decode

詳細はCommコマンドを参照してください。
